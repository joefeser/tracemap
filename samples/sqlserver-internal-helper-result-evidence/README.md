# Independent SQL Server internal-helper-result consumer fixtures
Compile/scan only; never invoke methods. No database or runtime values are needed.
C# and VB each have 14 `SqlDataAdapter.Fill` sites spread over several documents of one
project: four bounded `internal` / `Friend` helpers in `Helpers` (`ReadTable`, `ReadSet`,
`ReadTableText`, `ReadTableUsing`) and ten refused or uncalled helpers (`PrivateHelper`,
`PublicHelper`, `ProtectedInternalHelper` in `Bases`, `SplitPartialHelper` in `SplitA`,
`CrossDelegateHelper`, `CrossNameofHelper`, `GeneratedCallerHelper`, `LinkedCallerHelper`,
`LinkedFileHelper` in the linked `shared/LinkedHelpers`, `UncalledInternalHelper`). Callers live
in `Callers`, `MoreCallers`, `Helpers` itself, `SplitB`, the generated-named
`Generated/GeneratedCallers.g` (with an `<auto-generated/>` header) and `shared/LinkedCallers`,
which each project compiles through MSBuild `Link` from outside its project directory.
`Escapes` holds the method-group / `AddressOf` and `nameof` references. Method names match
across languages.
Result shapes are reused from [`../sqlserver-result-column-evidence`](../sqlserver-result-column-evidence/README.md).
See [the contract, syntax matrix and native commands](../../docs/validation/SQLSERVER_INTERNAL_HELPER_RESULT_EVIDENCE.md).
## Security analyzer boundary
The C# fixture's 14 rule-specific `nosemgrep` annotations apply only to
`csharp.lang.security.sqli.csharp-sqli`. These are deliberately varied source-analysis
inputs, compiled and scanned but never invoked; altering their command construction
would remove coverage. The fixture projects are libraries, not executables.
This is not a repository-wide SQL-injection exclusion or guidance for application SQL.
