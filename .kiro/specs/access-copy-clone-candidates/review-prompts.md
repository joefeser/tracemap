# Access Copy/Clone Candidate Review Prompts

## Evidence boundary

- Does every candidate begin with a qualifying persisted query kind?
- Can any object name, raw SQL, generic insert/update, or adjacency alone
  produce a clone conclusion?
- Are source/target direction, field mapping, parent/child ordering, generated
  keys, and dynamic behavior gaps rather than guesses?

## Provenance and determinism

- Does each candidate preserve exact supporting fact IDs, rule IDs, tiers,
  commit, span, extractor/version, coverage, and safe limitations?
- Are participant roles explicitly unknown?
- Are flow references matched by exact opaque query identity?
- Are all bounds explicit and deterministic under reversed input order?

## Privacy and non-claims

- Can raw names, SQL, VBA, expressions, literals, row counts, macro bodies,
  connections, customer identity, or local paths enter either artifact?
- Does all public wording remain candidate/needs-review?
- Does the report avoid execution, runtime, correctness, completeness,
  transactionality, production-use, migration-safety, and approval claims?

## Scope

- Did the change avoid Access COM, DAO, VBE, Windows, database files, row reads,
  exporter selection, and source-neutral contract widening?
- Are richer SQL/VBA/macro candidates clearly deferred behind a separately
  approved evidence mechanism?
