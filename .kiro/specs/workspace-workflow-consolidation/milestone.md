# Collection workspace milestone

## Owner story

As an application owner, I can configure web and framework sources once, verify
the selected inputs, and collect evidence into a fresh run with one start page.
I can opt into an existing prepared compiled publication and bounded offline SQL
definitions without constructing a target-framework build path or guessing which
diagnostic script owns the workflow.

## Delivered scope

- Strict `workspace init`, `verify` and `collect`, repository filtering, explicit
  Git identities, immutable prior runs and retained failures.
- `scripts/tm.ps1` publishes the CLI to a stable Release/Debug tool directory;
  its project owns the target framework.
- V1 source collection; V2 prepared native fresh source/compiled collection plus
  framework source; V3 SQL sidecar with optional compiled collection.
- Local ScriptDom definition collection and explicit whole-batch selection from
  larger original SQL templates, preserving hashes and original line mapping.
- A separate conditional DNN reader-wrapper syntax candidate command. It is
  outside workspace orchestration and does not establish compiler or runtime binding.
- One source start page, linked compiled/SQL guides, configuration reference,
  bounded public DNN trial results and a retained legacy workflow inventory.

## Acceptance evidence

- Owner completed synthetic source, source/compiled and source/compiled/SQL trials,
  including a web-only repository filter.
- Public DNN source trial used a pinned nine-file projectless slice. Explicit SQL
  selection admitted one table and one procedure under review-scenario settings.
  A later inspection retained five syntax observations, one conditional parameter
  candidate and nine unresolved boundaries. No DNN build or execution occurred.
- Full Debug solution with `-warnaserror`: 5,968 passed, three skipped, zero failed
  on implementation commit `42bbccbe4`. Subsequent packaging edits are docs only.
  Skips cover optional Oracle sweep, native HTTP receipt interop and Windows
  ASP.NET publication acceptance.
- Final focused candidate/local/selection/workspace/DNN lane: 109 passed,
  including 29 new candidate tests. Five public corpus cases and four retained
  SQL CLI smokes passed. Detailed local evidence is in `implementation-state.md`.

## Boundaries and follow-ups

Legacy scripts remain until output parity is demonstrated. Historical config
migration, workspace retained-source attach, retained-scan reuse/resume, retention
inventory and replacement agent instructions remain open. A full real application
trial with compiled publication and SQL is also open.

SQL sidecars are separate from raw/combined scan indexes. Selection does not
establish installed database state; selected result shapes remain unknown. The
source candidate does not prove compiler overload resolution, runtime dispatch,
external PetaPoco transport, event/hydration or result behavior. Broader SQL dump
compatibility and compiler-resolved binding need separately scoped work.

Inputs, outputs and fingerprints are local-only. The public story and PR describe
independently authored fixtures and pinned open-source material.
