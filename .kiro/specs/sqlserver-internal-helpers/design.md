# Design — internal helpers called from other documents of the same compilation
## Starting point (inspected before implementation)
- `SqlServerHelperResults` (Phase 4) admits only `private` helpers; its token reference scan
  walks the Fill's document. `internal` helpers are `helper-accessibility-unsupported`, and the
  Phase 4 smoke pins that (`InternalHelper`). That output must not change, so the widening is a
  new sibling state, not a change to `sqlserver-helper-result/2`.
- `DatabaseOperationApi.AddProperties` receives only the Fill invocation. Its semantic model's
  `Compilation` is the project compilation (`compilation.GetSemanticModel(tree,
  ignoreAccessibility: true)` in both adapters), so every syntax tree is reachable, but the
  project, repository root and scan-scope exclusions are not.
- Repo-relative paths come from `CSharpSemanticExtractor.ToRelativePathProjection(repoPath,
  path)`, which also reports paths outside the repository as external. Scan-scope exclusion
  (`RemoveExplicitlyExcludedSourceDocuments`) removes documents from the solution before
  compilation, so an excluded caller would silently vanish.
- `SqlServerSchemaEvidence.Json` writes null members, so a new nullable caller field on the
  Phase 4 records would change Phase 4 bytes and digests; Phase 5 uses its own records.
## Decisions
- **Distinct state.** `sqlServerInternalHelperResultState` (`sqlserver-internal-helper-result/1`)
  on every `data-adapter-fill` fact, beside the unchanged DataTable, DataSet and Phase 4 states.
  The Phase 4 analysis is shared (one engine with an accessibility mode) so the helper-body,
  signature and caller-consumer rules are literally the same code; Phase 4 output is unchanged.
- **Compilation scope.** Each adapter registers, per project compilation, a scope built from the
  project's documents (`SqlServerCompilationScopes.Register`, a `ConditionalWeakTable` keyed by
  the `Compilation`). A document entry is its repo-relative path or a typed gap. Scan-scope
  exclusion marks the filtered solution's affected projects as reduced. A compilation without a
  registered scope (explicit-context scans, direct API callers) is
  `helper-compilation-scope-unavailable`.
- **Caller path.** `callers[i].path` is the scope's repo-relative path of the caller document (the
  extractor's resolver; never absolute). Callers are ordered by (path ordinal, span start). The
  path is inside the caller entry, so the per-caller digest and binding include it.
- **Document classes** (first match wins): no project document for the tree (source generators,
  injected trees) or generated name (`.g.cs`, `.g.i.cs`, `.g.vb`, `.generated.cs/.vb`,
  `.designer.cs/.vb`, `.AssemblyInfo.cs/.vb`, `.AssemblyAttributes.cs/.vb`) or an
  `<auto-generated` / `<autogenerated` marker in the first 512 characters →
  `helper-generated-document-unsupported`; outside the repository, outside the project directory
  (MSBuild `Link`/`..` includes) or listed twice → `helper-linked-document-unsupported`; a
  repo-relative path outside the `[A-Za-z0-9._-]` segment vocabulary →
  `helper-document-path-unsupported`.
- **Bounds.** At most 1,024 syntax trees and 8,388,608 characters per compilation
  (`helper-compilation-limit`), checked before any reference scan; a text prefilter skips trees
  without the helper name; at most 64 call sites (`helper-caller-limit`, collection stops at the
  65th); each caller method keeps the 20,000-operation bound (`operation-limit`).
- **Errors.** Any compilation error the adapter itself counts against coverage (its
  `CompilationDiagnostic` gaps) is `helper-compilation-errors`: unresolved binding could hide a
  call. Amended during implementation: the first draft evaluated every error diagnostic, but VB
  MSBuildWorkspace loads always carry the location-less injected My-template errors that the VB
  adapter already excludes from coverage, so both adapters now pass their own decision.
- **Other compilations.** `InternalsVisibleTo` on the assembly →
  `helper-internals-visible-to-unsupported`. Without it, only reflection can reach an internal
  member from another compilation; that is never claimed. Calls into the helper from other
  compilations are never evidence.
- **Completeness.** Enumerated call sites are the compile-time invocations in the registered
  compilation only. Method-group, delegate, `AddressOf` and `nameof` references in any document
  make the whole helper `helper-reference-escape`. Reflection, dynamic dispatch and runtime
  caller completeness stay unclaimed.
- **Linked runtime matrix.** Not extended in this slice: the static widening is about document
  enumeration, which a single-process provider run does not observe. The unchanged linked
  harness (12/4/6, 42 checks) runs as a regression gate.
## Accepted syntax matrix
S = supported. Every other cell makes the whole helper state (helper rows) or one caller entry
(caller rows) `unknown` with the listed gap; first failing check wins in the order given.
### Helper (whole state)
| Area | Supported (S) | Unsupported → gap |
| --- | --- | --- |
| Fill, enclosing member, receivers, return | unchanged Phase 4 | unchanged Phase 4 gaps (`fill-overload-unsupported`, `helper-method-unsupported`, `fresh-*-required`, `operation-limit`, `helper-return-required`, ...) |
| Symbol | Phase 4 symbol rules (static, non-virtual, non-generic, non-async, non-extension, unique name, single-declaration types) with accessibility exactly `internal` / `Friend` | Phase 4 symbol gaps in Phase 4 order; `private` → `helper-private-phase4-scope` (Phase 4 evidence only); public, protected, protected internal, private protected → `helper-accessibility-unsupported`; assembly `InternalsVisibleTo` → `helper-internals-visible-to-unsupported`; partial method or multi-declaration type (including partial parts in other documents) → `helper-partial-type-unsupported`; same-name member → `helper-overload-ambiguous` |
| Signature, return type | unchanged Phase 4 | `helper-parameter-unsupported`, `helper-return-type-unsupported` |
| Scope | registered scope of a complete, error-free compilation within bounds, helper in an ordinary project document | `helper-compilation-scope-unavailable`; `helper-compilation-reduced`; `helper-compilation-limit`; helper document → `helper-generated-document-unsupported` / `helper-linked-document-unsupported` / `helper-document-path-unsupported`; `helper-compilation-errors` |
| References | invocations in every document of the compilation (≤ 64), each in an ordinary project document | reference inside the helper → `helper-recursion`; non-invocation reference in any document → `helper-reference-escape`; reference in a generated/linked/path-unsafe document → that document gap; > 64 → `helper-caller-limit` |
| Body | unchanged Phase 4 | unchanged Phase 4 gaps |
### Caller (one entry per call site, in any ordinary document)
Unchanged Phase 4 caller rules and gaps (arguments, fresh exact local, Phase 2 DataTable and
Phase 3 DataSet consumer rules bound to that local), plus `path`.
## Contracts
| Contract | Meaning |
| --- | --- |
| `sqlserver-internal-helper-result/1` | `sqlServerInternalHelperResultState`: the Phase 4 state fields (version, coverage, gap, resultKind, commandType, commandTextSource, adapterAssociation, fillOverload, tableName, helperLine, adapterLine, resultLine) and `callers`, each `{path, line, endLine, caller, coverage, gap, commandTextHash, resultLine, selectors, guards, accesses}`. |
| `sqlserver-internal-helper-result-bindings/1` | per call: `factId`, `callerIndex`, `commandText`, four-part `identity`, `internalHelperResultEvidenceSha256` (contract-tagged projection of the fact identity, the helper state without callers, the caller index and exactly that caller including its path). |
| `sqlserver-internal-helper-result-comparison/1` | rule `database.sqlserver.internal-helper-result-column-comparison.v1`; rows carry factId, callerIndex, callerPath, caller line span, caller member, accessIndex and admitted-shape provenance. |
CLI: `tracemap sqlserver-internal-helper-result compare` with the Phase 4 options →
`internal-helper-result-column-comparison.json`, `report.md`.
Comparison order is Phase 4's with `internal-helper-result-state-unavailable` and
`invalid-internal-helper-result-state` (adds an unsafe caller path); rows are Tier2Structural for
match/mismatch, Tier4Unknown otherwise; coverage `partial`, verdict `no-aggregate-clean-verdict`.
