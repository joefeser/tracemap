# Requirements — Phase 5: same-compilation internal helpers called from other documents
Follows Phase 4 (#917, merge `7169ee6e4`, branch `codex/sqlserver-consumer-helpers`). Exactly
one widening of the Phase 4 helper boundary in C# and VB: an `internal` (VB `Friend`) helper
whose call sites are enumerated across every document of the same compilation. Multi-level and
wrapper helpers, reader-returning helpers, `Field<T>`, named/typed DataSets, later result sets,
ORMs and DNN hydration stay separate later slices.
1. Source: the unchanged Phase 4 helper-body, signature, symbol and caller-consumer rules with
   one change: the helper is declared `internal` / `Friend` (not private, public, protected,
   protected internal or private protected) and its call sites are every invocation in every
   document of the same compilation. The accepted syntax matrix is authored in `design.md`
   before implementation; every other cell is unsupported.
2. Caller entries carry a repo-relative caller path produced by the extractor's normalized path
   resolver (`CSharpSemanticExtractor.ToRelativePathProjection`), never an absolute path, and the
   binding digest covers it.
3. Fail closed with typed gaps: `InternalsVisibleTo`, public/protected/private-protected
   helpers, partial types, a helper or reference in a generated document (generated name,
   `<auto-generated>` header or a compilation tree that is not a project document), a helper or
   reference in a linked or external document (outside the project directory or the repository),
   path-unsafe documents, compilations reduced by scan-scope exclusion, compilations with error
   diagnostics, unavailable compilation scope (explicit-context scans and direct callers), the
   whole-compilation document/size bound, method-group/`AddressOf`/`nameof` references in any
   document, more than 64 call sites, and every Phase 4 helper and caller gap. Private helpers
   remain Phase 4 evidence only.
4. Evidence: a distinct sibling property `sqlServerInternalHelperResultState`
   (`sqlserver-internal-helper-result/1`) on every Fill DatabaseOperationCandidate. The Phase 2,
   3 and 4 properties, refusals and outputs stay byte-for-byte unchanged in meaning (internal
   helpers remain `helper-accessibility-unsupported` in `sqlserver-helper-result/2`). Distinct
   bindings `sqlserver-internal-helper-result-bindings/1` bind one `(factId, callerIndex)` each;
   DataTable, DataSet, reader, parameter and Phase 4 bindings or digests never substitute. C#/VB
   extractor versions bump; historical records stay unknown.
5. Comparison: one separate route (`sqlserver-internal-helper-result`) over JSON, constant DDL
   and table-backed DDL shapes, each admitted by its unchanged origin route, with the shared
   Phase 2 column decision. Rows carry the caller path and span.
6. Claims: source tier preserved; caller completeness remains explicitly unclaimed (reflection,
   delegates, dynamic dispatch, other compilations); no claim that the helper or Fill executes,
   that tables or rows exist, about later result sets, values, types or nullability. Reports are
   partial with no clean verdict.
7. Independent public synthetic multi-document C#/VB fixtures with expectations authored before
   running the extractor, wired into `TraceMap.Tests.csproj` as `ReferenceOutputAssembly="false"`
   references and verified with no pre-existing fixture `bin/`/`obj/`; the same expectations in
   tests and a new native smoke with its own denominator. Derived artifacts carry exact generator
   SHA-256 and bounded-input SHA-256.
8. Validation: focused lanes, implementation commit, frozen full Debug `-warnaserror`, then
   sequential committed-head retained smokes with unchanged denominators (52-case 8/12/32 ×2;
   result JSON 36/10/36, DDL 36/10/58, 20 refusals; table per language 22/5/44, 24 refusals;
   DataTable per language 54/12/88 over 148 cases, 22 refusals; DataSet per language 78/12/88
   over 169 cases, 24 refusals; helper per language 42/15/58 over 115 cases, 24 refusals), the
   new smoke, Python guards, private-path and whitespace guards, the pinned C#/VB OSS smoke with
   honest reduced coverage, and the unchanged linked live harness (12/4/6, 42 runtime checks) on
   the reviewed disposable context. Push the branch. No PR, merge, ACK-policy change or paid
   review.
