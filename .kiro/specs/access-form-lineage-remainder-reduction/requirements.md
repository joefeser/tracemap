# Requirements

## Purpose

Reduce the remaining Microsoft Access form-lineage gaps with deterministic evidence already present in the base scan and protected design/VBA bundle, then establish the measured report-specific follow-up.

## Requirements

1. Recover unique saved-query output names from bounded static SELECT projections when DAO exposes no output-field catalog.
2. Keep output-name identity separate from source-field and runtime-result coverage.
3. Keep static binding lineage separate from runtime predicate/value coverage.
4. Resolve a uniquely declared VBA function used by an expression to its procedure stable key without persisting source text or claiming execution.
5. Resolve form filter identifiers against the scoped record source without inventing same-named control ambiguity.
6. Regenerate the provenance-compatible representative evidence and record exact before/after gap counts.
7. Begin the report-specific pass by classifying the remaining report gaps by deterministic family and next evidence need.

## Non-claims

- No query, VBA, macro, form, or report execution.
- No row reads, runtime values, branch outcomes, or result-shape proof.
- No arbitrary selection among ambiguous output, field, control, query, or VBA candidates.
