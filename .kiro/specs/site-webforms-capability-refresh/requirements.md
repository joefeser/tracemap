# Site Web Forms Capability Refresh Requirements

## Goal

Refresh the public capability, roadmap, legacy-modernization, manager, and
proof-path surfaces after the four bounded Web Forms stories reached `main`.
The refresh must preserve the claim level of each proof surface instead of
promoting the entire legacy .NET family.

## Requirements

1. The site SHALL present the guided terminal setup as `shipped`, the local
   synthetic replay and authored review walkthrough as `demo`, and the
   source-plus-compiled projection as `concept`.
2. Broad Web Forms event, route, navigation, postback, runtime, compatibility,
   and migration claims SHALL remain hidden, future, or explicit non-claims.
3. The capabilities, roadmap, manager packet, manager FAQ, manager proof-path,
   legacy .NET evidence, modernization evidence-map, and modernization
   handoff surfaces SHALL link the four proof stories without flattening their
   claim levels.
4. Automatic solution-wide discovery, backend microservice onboarding,
   cross-service click-to-database tracing, and source-server/PDB acquisition
   SHALL remain future work.
5. Repairs merged only to `dev` SHALL NOT be described as shipped on `main`.
6. Public copy SHALL distinguish static evidence, candidate bridges,
   unresolved values, partial coverage, and Windows-only validation.
7. Focused validation SHALL reject missing proof links, claim-level drift,
   future-work promotion, private material, and runtime or migration overclaims.

## Non-claims

- No runtime execution, customer compatibility, migration parity, complete
  coverage, complete cross-service tracing, release approval, or safety claim.
- No publication of customer screenshots, raw indexes, source snippets, SQL,
  secrets, connection material, local paths, or private validation output.
- No LLM calls, embeddings, vector databases, or prompt-based classification.
