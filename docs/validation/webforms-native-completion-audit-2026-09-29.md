# Native compiled Web Forms completion audit

Scope: the native operator workflow, deterministic public fixture parity,
immutable recovery, lossless grouped reports and bounded AI retrieval. This is
not private-site, ASP.NET compiler, runtime SQL, arbitrary graph capacity or
wrapper-retirement acceptance. The working PowerShell proof remains preserved.

## Final authorized Windows validation

Use an approved pinned .NET 10 tool installation. Prepare private `review.json`
with exact source commit, source/published roots, declared DLLs and existing
receipts. Do not infer those values from old TEMP folder names. For a retained
source scan use `operation: attach` and its exact `parentScanRoot`; for a fresh
run use `operation: fresh`. Use distinct new output roots for the two cases.

```text
tracemap webforms-review start --config review.json --out review-monday
tracemap webforms-review status --run review-monday/run --json
tracemap webforms-review resume --run review-monday/run
```

The first command produces both document sets under one workbench. If receipt
preparation is needed, only the owner may explicitly declare the exact
source-to-primary-DLL relationship using the native guide's attestation option.
No declaration means stop, not fabricate compiler provenance.

Compare the old and native method-chain identities, ordered transitions,
evidence variants, rules/tiers, source/DLL/parent provenance, coverage gaps and
review-only status. Verify completed resume changes no retained bytes. Review
the rendered workbench on Windows; the local browser tool denied file URLs, so
this audit does not claim a new interactive browser check. Renderer/navigation
tests and retained HTML are separate evidence, not a visual substitute.

Keep both runs and all dependencies. Return only safe counts, categorical gap
reasons and pass/fail status; do not upload private paths, source, DLLs, handoffs
or fingerprints. Retiring wrappers, deleting proof folders and merging still
require their separate approvals.
