# Bounded offline SQL Server internal-helper-returned DataTable/DataSet evidence (cross-document callers)
Phase 5 after Phase 4 (#917, merge `7169ee6e4`). One question inside an explicit static subset:
**does a constant DataRow column-name or ordinal read, through the DataTable (or first DataSet
table) returned by one bounded `internal` / `Friend` static helper called from any ordinary
document of the same compilation, agree with the admitted first-result shape of the procedure
that this call site passes?** The static corpus is public synthetic, compiled/parsed and never
executed. Every report is `partial` / `no-aggregate-clean-verdict`. Not DNN,
private-application, deployment or migration acceptance.
## Contracts and route
| Contract | Meaning |
| --- | --- |
| `sqlserver-internal-helper-result/1` (`sqlServerInternalHelperResultState`) | Sibling of the DataTable, DataSet and Phase 4 `sqlServerHelperResultState` properties on every `data-adapter-fill` DatabaseOperationCandidate (no new fact type). Same helper fields as Phase 4; `callers[i]` adds `path`, the caller document's repo-relative path from the extractor's resolver (`CSharpSemanticExtractor.ToRelativePathProjection`), never absolute. Callers are ordered by (path, position). C# `csharp-semantic/0.22.18`, VB `vb-semantic/0.10.21`. |
| `sqlserver-internal-helper-result-bindings/1` | One binding per call site: `factId`, `callerIndex`, two-part command text, four-part identity and `internalHelperResultEvidenceSha256` (contract-tagged projection of the fact identity, the helper state without callers, the caller index and exactly that caller including its path). |
| `sqlserver-internal-helper-result-comparison/1` | Rows under `database.sqlserver.internal-helper-result-column-comparison.v1` carrying `callerIndex`, `callerPath`, the caller line span and calling member. |

## Accepted syntax (summary; full matrix in the spec design)
[`.kiro/specs/sqlserver-internal-helpers/design.md`](../../.kiro/specs/sqlserver-internal-helpers/design.md)
lists every cell and gap, authored before implementation. Exactly one widening of Phase 4:
- helper: the unchanged Phase 4 helper-body, signature and symbol rules with accessibility
  exactly `internal` (VB `Friend`); private helpers are `helper-private-phase4-scope` here and
  stay Phase 4 evidence; public, protected, protected internal and private protected helpers
  are `helper-accessibility-unsupported`;
- callers: every invocation in every ordinary document of the registered compilation (at most
  64), each a separate entry under the unchanged Phase 4 caller rules plus its path.
Whole-helper typed unknowns: `helper-internals-visible-to-unsupported` right after the
accessibility check, `helper-partial-type-unsupported` (including partial parts in other
documents) where Phase 4 checks it, and, after the unchanged signature and return-type checks,
in this order: `helper-compilation-scope-unavailable` (explicit-context scans, direct
API callers), `helper-compilation-reduced` (scan-scope exclusion removed documents),
`helper-compilation-limit` (more than 1,024 trees or 8,388,608 characters),
`helper-generated-document-unsupported` / `helper-linked-document-unsupported` /
`helper-document-path-unsupported` for the helper's document, `helper-compilation-errors`, then
`helper-recursion`, `helper-reference-escape` (method group, delegate, `AddressOf`, `nameof` in any
document), the document gap of any referencing document, and `helper-caller-limit`.
Document classes: a tree that is not a project document (source generators, injected trees), a
generated name (`.g.cs`, `.g.i.cs`, `.g.vb`, `.generated.*`, `.designer.*`, `.AssemblyInfo.*`,
`.AssemblyAttributes.*`) or an `<auto-generated`/`<autogenerated` marker in the first 512
characters is generated; a document outside the repository, outside the project directory
(MSBuild `Link` or `..` includes) or listed twice is linked; a path outside the
`[A-Za-z0-9._-]` segment vocabulary is path-unsafe.
## Decisions
- Distinct state: the Phase 4 state and smoke pin internal helpers as
  `helper-accessibility-unsupported`, so widening `sqlserver-helper-result/2` would change
  retained output. The Phase 4 analysis is shared code with an accessibility mode.
- Compilation scope: both adapters register, per project compilation, the document classes and
  the adapter's own coverage-reducing error decision (its `CompilationDiagnostic` gaps; the VB
  adapter's location-less injected My-template diagnostics stay excluded as before). Scan-scope
  exclusion marks the filtered solution's projects reduced.
- Caller completeness is never claimed: reflection, dynamic dispatch and other compilations are
  not observed. Without `InternalsVisibleTo`, other compilations reach internal members only
  through reflection.
- The linked runtime matrix is not extended in this slice; it runs unchanged as a regression gate.
## Comparison
Per Fill fact: unsupported source; `internal-helper-result-state-unavailable`; helper gap; command
type; `invalid-internal-helper-result-state`; no callers → `helper-caller-unavailable`. Otherwise
per caller: caller gap or `invalid-internal-helper-result-state` (including an unsafe caller
path); `binding-missing`; `exact-result-shape-unavailable`; `command-binding-conflict`; then the
shared Phase 2 DataRow decision per access or `no-bounded-column-access`.

## Non-claims and remaining unknowns
Privacy: comparison JSON and Markdown are **local evidence reports, not sanitized shareable
exports**; they retain repo-relative source and caller paths, caller identities and column
names. Keep reports and provenance hashes from private inputs private.
Not proven: that the helper or Fill executes, that the enumerated call sites are all runtime
callers, that any table or row exists, later result sets, values, types, conversions,
nullability, runtime exceptions, catalog/live/deployed correspondence. Outside scope:
multi-level, instance, public, protected, generic or wrapper helpers, callers in other
compilations, reader-returning helpers, `Field<T>`, named/typed DataSets,
`DataColumn`/`DataRowVersion` access, ORMs, DNN hydration and provider wrappers.
